## Decision

Stripe integration (payments-service, marketplace-service checkout, webhook handling) is **deferred from the initial production launch**.

EasyPost has been **removed entirely** — not just deferred. The shipping provider is undecided.

## Reason

**Stripe**: Not yet fully set up and tested. Launching without it avoids blocking auth, cards, collection, and messaging.

**EasyPost**: Free tier limited to 50 labels/month and charges extra for tracking. Not viable at scale.
**Shippo**: Ruled out — US-based, UK carrier support costs $20/carrier/month.
A UK-native provider will be selected separately.

## Current state

- `apps/marketplace-service/src/services/shipping.service.js` — replaced with a not-implemented stub
- `POST /orders/:id/shipping-rates` — returns `501 Not Implemented`
- `POST /orders/:id/ship` — still works with manual `trackingNumber` + `trackingCarrier` in body
- EasyPost tracking webhook (`/webhooks/easypost`) — removed
- `@easypost/api` package — removed from marketplace-service
- `shipping-service` container — removed from docker-compose (no source code existed)

## Implications

- `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` are deferred secrets — do not block launch
- `EASYPOST_API_KEY` and `SHIPPO_API_KEY` are gone — do not add back without a provider decision
- Sellers can manually enter a tracking number when shipping; label generation is not available
- Revisit shipping provider selection before enabling marketplace fulfilment
