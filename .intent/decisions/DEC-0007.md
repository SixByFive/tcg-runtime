## Context

Clients (mobile, web) need real-time push events (chat messages, notification badges, trade updates). Options: expose realtime-service directly (another public port) or proxy through the gateway.

## Decision

The realtime-service (port `4018` internally) is **not** exposed publicly. Clients connect via the gateway, which proxies WebSocket / SSE connections. This keeps the public surface minimal — only port `4010` is exposed.

The realtime-service receives push payloads from other services via `POST /internal/push` (guarded by `x-internal-key`). It then fans out to connected clients by userId using Redis pub/sub for horizontal scale.

Mobile clients connect using the Socket.IO URL configured as `EXPO_PUBLIC_SOCKET_URL` (proxied through gateway).

## Consequences

- One public port for all traffic (HTTP + WS).
- Gateway acts as WebSocket proxy — adds latency hop but simplifies security posture.
- Redis pub/sub required if realtime-service runs multiple instances.
- Realtime-service port `4018` internal; the `4020` port referenced in some mobile config is the host-mapped port for local dev.
