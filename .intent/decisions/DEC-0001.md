## Context

Microservice architectures typically use one database per service for true isolation. However, this has high operational overhead (many DB instances, complex cross-service joins, eventual consistency). For an early-stage platform, a single MySQL database with logical separation is a pragmatic trade-off.

## Decision

All services share a single MySQL database (`sixbyfive_tcg`). Each service **owns** a defined set of tables — it is the only service that runs `Model.sync()` on them. Other services may read across service boundaries using read-only Sequelize models with `sync: false`, but must never write to tables they don't own.

Table ownership is documented in `docs/architecture/database-ownership.md`.

## Consequences

- Simpler operational setup (one MySQL instance).
- Cross-service reads possible without HTTP calls (worker reads marketplace tables directly).
- Risk: tight coupling at DB level — a schema migration in one service can affect readers.
- Production schema changes in owned tables require manual SQL migration before redeploy (no `alter` in prod).
- If services are ever fully separated, cross-service models become HTTP calls.
