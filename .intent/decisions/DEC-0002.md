## Context

With 10+ microservices, clients (web, mobile) cannot talk to each service independently — the surface area is too large, versioning becomes a nightmare, and auth would need to be duplicated everywhere.

## Decision

The **Gateway** (port 4010) is the single externally-exposed service. All clients — web browser and mobile app — make GraphQL requests to the gateway. No downstream service exposes a public port.

The gateway:
- Verifies the user's JWT
- Injects `user` into resolver context
- Fans out to downstream services via HTTP (`@sbf/contracts` internal clients)
- Merges responses (e.g. `hydrateCards` joins catalog data onto collection entries)

All downstream service ports are `internal only` in Docker Compose.

## Consequences

- Clients have one endpoint to learn.
- Gateway is the single choke point — it must be highly available.
- Adding a new domain requires a gateway schema update + new resolver + new internal client.
- No REST API for external clients — GraphQL only.
