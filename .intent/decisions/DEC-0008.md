## Context

Background tasks (escrow expiry, offer expiry, price alert checks, wishlist fan-out) could live inside their respective domain services or be centralised in a dedicated worker.

## Decision

All scheduled jobs live in **worker-service** (port `4020`). It uses `node-cron` for scheduling. The worker reads cross-service tables directly (using read-only Sequelize models with `sync: false`) and calls other services' internal APIs for side effects.

Jobs:
- Escrow expiry — reads `marketplace_orders`, auto-resolves expired escrows
- Offer expiry — reads `offers`, expires stale offers
- Trade top-up expiry — reads `trades`
- Price alert check — reads `price_alerts` + `m_prices`, fires notifications
- Wishlist fan-out — reads `wishlist_items`/`wishlists`, fans out match alerts

## Consequences

- Domain services stay focused on their own writes — no cron code scattered across services.
- Worker has read access to multiple services' tables, creating cross-service DB coupling (accepted trade-off per DEC-0001).
- Worker's `node-cron` schedule honours `CRON_TZ` (default `Europe/London`).
- If worker-service crashes, scheduled jobs stop silently — add alerting in production.
