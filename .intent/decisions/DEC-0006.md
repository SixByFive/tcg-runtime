## Context

The gateway schema has two query fields that do the same thing:

- `searchCards(input: CardSearchInput!): CardSearchResult!`
- `cardsearchSearchCards(input: CardSearchInput!): CardSearchResult!`

The `cardsearch*` prefix was added during the mobile API migration to namespace catalog operations clearly. The unprefixed `searchCards` was kept for backward compatibility with existing web clients.

## Decision

Both fields are kept in the schema and both resolve identically. Neither is deprecated yet. The mobile app uses `searchCards`; the web app may use either.

The broader `cardsearch*` naming convention for catalog queries:
- `cardsearchCard(id, variant)` — single card
- `cardsearchSearchCards(input)` — search (aliased as `searchCards`)
- `cardsearchSets(limit, offset)` — sets list
- `cardsearchSetByCode(code)` — single set
- `cardsearchPriceObservations(...)` — price history
- `cardsearchPriceRollups(...)` — price summary

## Consequences

- Schema has two names for the same operation — mild confusion, but manageable.
- If the unprefixed form is ever removed, web clients must be updated.
- Do not add further aliases without a clear migration plan.
