## What

In production (`NODE_ENV=production`), all services must use `Model.sync({ force: false })` only — this creates missing tables but **never modifies existing columns**. `{ alter: true }` (dev mode) and `{ force: true }` (wipe + recreate) are both prohibited in production.

## Why

- `alter: true` can drop columns, rename types, or cause data loss on live tables.
- `force: true` drops and recreates tables, destroying all data.
- Production schema changes must be applied as manual SQL migrations before redeploying.

## How to manage

The `NODE_ENV=production` env var (set by `.env.shared.docker`) triggers safe sync mode. Before deploying a service with a schema change:
1. Write the migration SQL (`ALTER TABLE ...`, `ADD COLUMN ...`)
2. Apply it to the production DB manually
3. Deploy the updated service

Never promote a dev build (with `NODE_ENV=development`) to production.
