## What

The `ACCESS_TOKEN_SECRET` environment variable must have **the same value** in:
- `auth-service` (signs tokens)
- `gateway` (verifies tokens on every request)
- `marketplace-service` (verifies tokens on protected routes)
- `payments-service` (verifies tokens)
- `realtime-service` (verifies tokens on WS/SSE connect)

## Why

JWTs are signed with `ACCESS_TOKEN_SECRET`. If any verifying service uses a different secret, it will reject all tokens as invalid. This is a hard constraint — mismatching secrets will cause silent auth failures that are hard to debug.

## How to manage

Set `ACCESS_TOKEN_SECRET` once in `env/.env.shared` so all services inherit the same value. Do not override it per-service. In Docker, it flows through `.env.shared.docker`.

Generate with: `openssl rand -hex 64`
