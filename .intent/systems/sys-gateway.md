## Overview

The Gateway is the single public entry point for all clients (web, mobile). It runs on port `4010` and exposes a unified GraphQL API that fans out to downstream microservices.

## Key files

| File | Purpose |
|------|---------|
| `apps/gateway/src/graphql/schema.js` | Full GraphQL type definitions (all types, queries, mutations) |
| `apps/gateway/src/graphql/resolvers.js` | Resolver implementations + `hydrateCards` helper |
| `apps/gateway/src/graphql/context.js` | Request context: user, service clients, logger |
| `apps/gateway/src/clients/` | HTTP clients for each downstream service |
| `apps/gateway/src/middleware/` | Auth middleware (JWT verification, `x-internal-key` guard) |
| `apps/gateway/src/app.js` | Express + Apollo Server setup |
| `apps/gateway/schema.graphql` | Exported schema snapshot (generated by `pnpm schema:export`) |

## Schema highlights

- `cardsearchCard(id, variant)` — single card detail
- `searchCards(input: CardSearchInput!)` / `cardsearchSearchCards(input:)` — both aliases work
- `cardsearchSets(limit, offset)` — set list
- `unreadMessageCount` — messaging badge count
- `searchUsers(q: String!, limit: Int)` — user search (variable is `q` not `query`)
- Mobile auth: `login` / `register` return `AuthPayload` with token in JSON body

## Card hydration

Collection, wishlist, and binder entries are stored in collections-service with only a `cardId`. The gateway's `hydrateCards()` helper batch-fetches full card data from catalog-service and merges it onto the entries before returning. Falls back gracefully if catalog is down.

## Port

`4010` — only service exposed publicly. All others are internal-only.
